# Public Launch Checklist

This checklist separates repository readiness from public promotion.

## Repository

- [x] Clear product boundary in README.
- [x] Architecture documentation.
- [x] Security policy.
- [x] Signed GitHub Releases updater channel.
- [x] Gemini Spark / Google Workspace integration findings.
- [ ] Public-safe product screenshots or a short demo GIF/video.
- [ ] Decide whether to keep the current all-rights-reserved license or adopt a recognized open-source license.
- [ ] Add repository About description and topics if they are still missing.

## Product validation

- [ ] Confirm the latest installed release auto-updates successfully from the previous version.
- [ ] Verify close/minimize/maximize/drag on a real Windows machine.
- [ ] Verify Spark sign-in persists after restart.
- [ ] Verify Drive, Docs, and Sheets opened by Spark launch in Google Chrome and load reliably.
- [ ] Verify a failed update check never blocks application launch.

## Public presentation

- [ ] Record a 20–40 second clean demo using a test Google account or non-sensitive content.
- [ ] Avoid exposing personal documents, email addresses, account avatars, phone numbers, or private prompts.
- [ ] Show the product exactly as it behaves; do not imply official Google endorsement.
- [ ] Use Spark Desktop's own visual identity for project graphics rather than Google/Gemini logos as the project logo.

## Outreach

- [ ] Publish the GitHub repository announcement.
- [ ] Submit concise product feedback from Gemini Apps with the repository/findings link.
- [ ] Post a technical case study in the Gemini Apps Help Community.
- [ ] Publish a developer-oriented post linking to `GEMINI_SPARK_DESKTOP_FINDINGS.md`.
- [ ] Share a short launch post on professional/social channels.

## Follow-up

- [ ] Convert useful community feedback into GitHub issues.
- [ ] Keep a short changelog for public releases.
- [ ] Avoid expanding Spark Desktop into a general-purpose browser unless the product direction explicitly changes.
